# Настольная нода Minter

Tauri 2, Svelte 5 и TypeScript используют `minterd` и `minterctl` из той же поставки. Полная нода работает через нативный режим синхронизации. Лёгкий режим хранит проверенные заголовки в redb и запрашивает два Tendermint RPC. Библиотека `minter-node-control` задаёт общий формат настроек и жизненный цикл для GUI и foreground CLI.

## Первый выпуск интерфейса

- Выбор режима, каталога данных и политики хранения.
- Первый запуск от genesis или пакета со снимком и доверенным SHA-256. Продолжение существующей базы.
- Запуск, штатная остановка и перезапуск ноды. Закрытие окна сворачивает приложение в трей. Выход из трея останавливает управляемую ноду.
- Статус полной ноды из локального Minter v2 API. Подключение к ноде, запущенной из CLI.
- Статус и регулярная синхронизация лёгкого клиента через существующие команды `minterctl light`.
- Восстановление проверенной высоты из redb после повторного открытия GUI при недоступных RPC. Предупреждение при истечении доверия.
- Сохранение настроек отдельно от блокчейна, ограниченный журнал, ошибки запуска и сетевых запросов.

Первоначальные источники доверия задаются в настройках. Публичная доставка снимков и доверенных точек остаётся отдельной задачей общего плана.

## Профили хранения и общий CLI

Новый профиль полной ноды по умолчанию сохраняет 120 версий состояния, 100 000 полных блоков и высот событий. Архивный профиль сохраняет дальнейшие данные без очистки. В профиле со своими лимитами ноль отключает очистку соответствующих данных; один полный блок недопустим. Переключение в архив не восстанавливает удалённую историю, а запуск от снимка ограничивает начальную границу данных.

Старые настройки `archive: false` мигрируют в свои лимиты: прежний `keepVersions`, без лимита блоков и событий. Прежний архивный режим остаётся архивным. Миграция не включает новую очистку блоков автоматически.

```sh
minterctl node init --config ./settings.json --data-dir ./node
minterctl node settings --config ./settings.json
# Укажите в JSON источники доверия и подключения либо используйте файл настроек GUI.
minterctl node run --config ./settings.json
minterctl node status --config ./settings.json
minterctl node logs --config ./settings.json
```

Ctrl-C останавливает CLI-супервизор; `--shutdown-on-stdin-close` подходит для запуска из другого приложения. Конфигурация и папка данных блокируются на время управления. GUI подключается к полной ноде внешнего CLI через общий локальный IPC; статус и штатная остановка доступны из обоих интерфейсов. Таймаут остановки составляет 40 секунд, принудительный выход сообщает ошибку. Импорт снимка, обязательная история и очистка получили кооперативную отмену и повтор; оставшиеся части обслуживания и genesis перечислены в текущем статусе alpha. [Контракт и ограничения](../docs/specs/desktop-node-control.md).

## Проверка

```sh
npm ci
npm run format:check
npm run check
npm run build
node tools/prepare-binaries.mjs <каталог-с-minterd-и-minterctl>
npm run tauri build -- --no-bundle
```

Для прямой production-сборки через Cargo сначала соберите frontend, затем добавьте `--features tauri/custom-protocol`. Обычный `cargo build --release` сохраняет ожидание dev-сервера из `devUrl`.

Rust-проект GUI имеет собственный workspace и lockfile. Данные сохраняются в выбранном каталоге, настройки — в каталоге приложения операционной системы. GUI передаёт аргументы бинарникам напрямую через API процессов Rust.

Переменная `MINTER_DESKTOP_HOME` позволяет выбрать отдельный каталог настроек и исходный путь данных для переносимого профиля. Проверки используют выделенный профиль.

В выбранной папке профиль полной ноды занимает подпапку `state`, лёгкий клиент — файл `light.redb`. Журнал `node.log` и предыдущий файл `node.log.1` ограничены двумя МиБ каждый. Для обновления доверенной точки лёгкого клиента выберите новую папку данных и файл нового заголовка.

Полная нода получает `--shutdown-on-stdin-close`. При штатном выходе GUI закрывает stdin и ждёт завершения `minterd`. Потеря процесса GUI также закрывает канал. На Windows дочерние консольные окна скрыты.

Сценарии приёмки включают кириллицу и пробелы в путях, ошибку параметров, занятый порт, повторный запуск, закрытие и открытие окна, сохранение высоты после остановки, запуск обеих платформ и сверку экрана с настоящим API.

## Установочные пакеты

На Windows пакет собирается командой `npm run tauri build -- --bundles nsis`. Текущая сборка использует установку в профиль пользователя. Подпись релиза задаётся отдельно при подготовке выпуска.

На Ubuntu 24.04 соберите бинарники в одной папке, затем вызовите упаковщик из корня репозитория.

```sh
bash desktop/tools/package-linux.sh <каталог-бинарников> <каталог-пакетов>
sudo apt install ./minter-node_0.1.0_amd64.deb
```

Пакет устанавливает `minter-node` и пункт меню Minter Node. Для GUI требуется WebView2 на Windows или WebKitGTK 4.1 на Ubuntu.

## Сквозной сценарий

```text
python -B desktop/tools/verify-desktop.py <gui> <tauri-driver> <native-driver> <minterctl> <tendermint-0.34.19> <go-abci> <go-fixture-directory> <new-results>
```

Windows использует Edge WebDriver той же версии, что WebView2. На Linux используется `WebKitWebDriver`. Сценарий создаёт два локальных Go-пира, открывает настоящий WebView приложения, нажимает кнопки запуска, перезапуска и остановки и сверяет AppHash с Go. Затем он проверяет подключение к отдельному CLI-процессу, работу redb, форму настроек, истечение 15-секундного доверия и повторное открытие GUI после остановки обоих RPC. Профиль теста создаётся внутри каталога результатов.

В предыдущей сборке `cec02b0` пройдены Windows 11 x64 и Ubuntu 24.04 в контейнере с Xvfb, ядро WSL2. Windows-прогон использовал файлы из NSIS. Linux-прогон использовал установленный через `dpkg` пакет и обычного пользователя UID 1000. Испытания закрытия окна с активной нодой, обновления и удаления установщика и запуска на чистых графических ОС остаются в общем плане.

Отдельный сценарий `tools/verify_node_controller.py` проверяет общий CLI без GUI на реальных Go-пирах: профили в RocksDB, конфигурационную блокировку, ошибки дочернего процесса, ожидание light-команды при закрытии stdin и терминальном SIGINT в Linux. Результаты новой интеграции с актуальным ядром и результаты прежних установщиков учитываются раздельно.

15 ноября 2026 повторно пройдены production WebView-сборки Windows 11 и Ubuntu 24.04 в контейнере с Xvfb/WSL2, пользователь UID 1000. Профили full → archive → full → custom проверены через форму и фактическую политику RocksDB; общий CLI проверен также на Ubuntu 24.04 с ядром 6.8.0-149 в QEMU. По 123 теста workspace и Clippy пройдены в Windows и Linux/WSL2. Эти прогоны не заменяют проверку обновлённых установщиков и чистой графической Ubuntu.

В Docker для Xvfb используйте `--init`: запуск `xvfb-run` непосредственно как PID 1 может остановиться на ожидании сигнала готовности. Время блока локальной Go-фикстуры задаётся 1100 мс, чтобы при длинном прогоне заголовки не уходили вперёд часов стенда.
