# ADR-002: дополнение commit после исполнения блока

14 ноября 2026 года. Принято для нативного консенсуса Tendermint 0.34.

## Причина

В самостоятельной сети четырёх Rust-валидаторов приложение успешно исполняло блок сразу после трёх precommit. Переход на следующую высоту отбрасывал последующие голоса прежней высоты. Обработка локального голосования только таймером также позволяла получить чужой кворум раньше собственного precommit. В прогоне Ubuntu это привело к отключению одного валидатора на H+2 после EndBlock 137. Go воспроизвёл то же состояние: правила Minter исполнялись правильно, но нормальные подписи терялись при построении следующего блока.

## Решение

Обработка сообщения текущей высоты сразу продвигает существующий автомат локального голосования. Состояние подписанта, порядок блокировок и запрет конфликтующей повторной подписи сохраняются.

Для непосредственно предыдущей высоты принимаются только precommit нужного раунда. Подпись проверяется в контексте цепочки и набора валидаторов **предыдущего блока**, включая индекс и адрес. Подпись может заполнить только Absent; уже сохранённая подпись не заменяется. Голос за другой блок не дополняет commit. Nil сохраняется с соответствующим флагом. Полный расширенный commit повторно проверяется как сертификат того же BlockID с достаточным весом.

`BlockRecord.commit` дополняется одной синхронной записью RocksDB. Запись разрешена только на текущей сохранённой высоте и при совпадении прежних байтов записи. Операция выполняется под общей блокировкой `NativeNode`, не изменяя block response, корень IAVL, высоту, результаты ABCI или метаданные исполнения. При отказе записи автомат останавливается. Схема protobuf остаётся прежней; миграция базы не требуется.

Расширенный commit восстанавливается при открытии базы и используется для будущего предложения. Уже подписанное предложение и его байты не переписываются. Пирам на шаге `NewHeight` распространяются сохранённые precommit предыдущей высоты. Историческая выдача частей продолжает использовать исходный блок и проверенный commit.

## Цена и проверка

Новая поздняя подпись вызывает дополнительную синхронную запись записи блока; повторы её не вызывают. Память ограничена одним предыдущим commit. Кворум и правила исполнения Minter не меняются.

Регрессионный тест создаёт блок с тремя подписями, доставляет четвёртую после исполнения и проверяет её после повторного открытия RocksDB. Он также проверяет неверную подпись, повтор, неизменность высоты, AppHash и исходного блока. Сквозной стенд требует неизменного набора из четырёх валидаторов, включая 32 блока после общего перезапуска, и последующего исполнения цепочки обычной Go-нодой. Смешанный сценарий отдельно проверяет переход 4→3 на H+2.
