# Смена ключа и контекст замороженных средств

Статус: принято; 14 ноября 2026.

## Причина

Go `EditCandidatePublicKey` меняет публичный ключ модели при сохранении ID. Старый ключ становится запрещённым, новый требует полного обновления валидаторов в EndBlock. Порядок проверок, газ и события входят в совместимость приложения.

Go также сохраняет в новых frozen funds, созданных при наказании кандидата, указатель на поле ключа модели. Кеш frozen funds переживает Commit. Ротация меняет логический источник такого остатка, но сама не помечает ранее записанную строку frozen funds изменённой. Следующая запись той же высоты сериализует уже новое значение. Событие выдачи остатка хранит этот указатель до CommitEvents, поэтому ротация после BeginBlock меняет и ранее созданное событие.

Генератор `tools/make_candidate_key_fixture.go --frozen-keys` воспроизводит это на настоящем Go-executor: запись H701, ротация H702 без записи, добавление нового остатка H703, ещё одна ротация H704 и выдача H1232. Отдельный Go-импорт после H704 восстанавливает физический ключ из IAVL и теряет ссылку. Это свойство исходного Go-кеша, а не новое правило дерева.

## Решение

Rust хранит `frozen_references` в служебном `Chain` отдельно от IAVL. Запись содержит будущую высоту, диапазон индексов и текущий логический ключ. Последовательные остатки одного кандидата объединяются в диапазон; отдельный ключ на каждую делегацию не нужен.

Только создание соответствующих новых остатков регистрирует ссылку. Импортированные остатки, обычные Unbond/Move и Lock её не получают. Ротация меняет логические ключи ссылок, сохраняя прежние физические байты до необходимой записи. Push, обработка существующих остатков, выдача и Commit применяют ссылки в нужной фазе. При выдаче диапазон удаляется; связанные UnbondEvent остаются обновляемыми до Commit текущего блока.

Контекст записывается атомарно с головой и состоянием. Повторное открытие Rust продолжает непрерывную трассу Go, включая её служебный кеш. При чистом импорте физического Go-снимка контекст пуст, как у свежего Go-импорта. Формат RLP и AppHash не расширяются.

## Пакеты снимков

Нативный пакет Rust добавляет необязательное поле `frozenReferences` в манифест, покрытый доверенным `checkpointSha256`. При импорте проверяются будущие высоты, наличие физических записей, границы и отсутствие пересечения диапазонов, а также согласованные ненулевые ID кандидатов и существующие ключи в соответствующих остатках. Те же проверки выполняются при открытии сохранённого состояния и экспорте пакета.

Отдельный файл `snapshot.zlib` сохраняет исходный формат Go с прежним набором AppDB store names. Импорт такого файла соответствует свежему Go-импорту. Пакет Rust сохраняет дополнительный контекст для продолжения работы Rust-узла.

Экспорт, импорт, чтение истории пакета и serving используют общий предел манифеста 1 МиБ. Экспорт проверяет его до публикации каталога. Регрессионный тест serving принимает описание больше прежних 16 КиБ и отклоняет превышение общего предела.

## Выплата и совместимость

Смена ключа действующего валидатора точно на блоке выплаты приводит закреплённый Go к panic в PayRewards: старый набор валидаторов ещё используется, а старого ключа в кандидатах уже нет. Rust возвращает ошибку EndBlock и сохраняет прежнюю зафиксированную голову. После открытия заново контрольный блок без ротации совпадает с Go. Перенос обновления валидаторов перед выплатой изменил бы исходный порядок и здесь не применяется.

Историческая совместимость остаётся отдельным критерием общего плана. Для сетевой смены подписанта на H+2 и передачи пакета с непустым контекстом добавлен самостоятельный смешанный Go/Rust-сценарий; он использует [доверенный genesis пользовательской сети](0008-checkpoint-genesis.md), State Sync и отрицательный контроль без контекста.
