# Перевыпуск и история моделей монет

Статус: реализовано; контракт — [coin-recreation](../specs/coin-recreation.md).

`RecreateCoin` (0x10) и `RecreateToken` (0x1f) используют существующий RLP-парсер полей выпуска, отдельные комиссии и gas=5 до общих надбавок. Перевыпуск не создаёт новый тикер и не списывает цену его регистрации. Порядок basicCheck отличается от Create и повторяет закреплённый Go.

План операции сохраняет ID и модель прежней текущей монеты, полную историю символа и новый ID. Прежняя модель получает максимальную версию истории плюс один, новая — версию 0. Явный `wrapping_add` воспроизводит uint16 Go: при максимуме 65535 прежняя модель тоже получает 0. Поиск текущей версии сохраняет первый подходящий ID в истории; mint проверяет version самой монеты, как Go. Самовольный отказ переполнению изменил бы результат исполнения.

`coins::Changes` отдельно хранит изменённые модели существующих ID. Это позволяет записать новую version без лишней записи supply и сохранить уже проведённое списание gas из той же монеты. История символа содержит старые и новые ID, видимые следующим транзакциям блока. Для монеты, созданной в этом же блоке, обновляется её уже подготовленная модель.

Владелец относится к символу, поэтому EditCoinOwner должен быть виден и после следующего перевыпуска. Текущий ID при обычном перевыпуске увеличивается; при uint16-переполнении поиск оставляет первый version=0. Он не движется назад, поэтому последний владелец определяется по наибольшему изменённому текущему ID. При Commit используется его окончательное значение и общий dirty-флаг символа, повторяющий Go SymbolInfo. Это предотвращает запись прежнего владельца из более ранней операции блока.

Запись сохраняет убывающий порядок dirty ID: список тикера у созданного ID, изменённая модель, supply при его изменении и сведения владельца. Новые версии не удаляют прежние балансы, резервы, пулы или стейки. Новый резерв отдельно списывается в BIP; проверяются gas, сам резерв и, для BIP gas, их общая сумма.

Форматы IAVL, RocksDB и API не расширены. Служебного контекста вне физического дерева для перевыпуска не добавлено. Корпус проверяет непрерывное исполнение Go, экспорт/импорт AppState и настоящее повторное открытие Go StateDB с пустым Coins.list; Rust открывается заново после каждого блока.

Go-корпус охватывает оба направления coin/token, повторные операции в блоке, смену владельца, mint прежней версии, нулевую и отличную от BIP цену, gas в перевыпускаемой резервной монете и в перевыпускаемом токене через его пул, ошибки и uint16-границу. CheckTx — изолированные пробы активного ExecutorV3 с minGasPrice=1; отдельный запуск Tendermint-мемпула этим не заявляется.

В `tests/coin_recreation.rs` сравниваются полные ABCI, корни и физические ключи; после каждого блока выполняется экспорт/импорт IAVL. `tools/verify_coin_recreation.py` проверяет реальные daemon-процессы, остановки вокруг Commit и ICS23-доказательства сохранённых coin keys. Исторические случаи и все прежние правила остаются отдельной частью приёмки.
