# Привязка нативного checkpoint к genesis

Статус: реализовано. Спецификация — [native-checkpoint-genesis](../specs/native-checkpoint-genesis.md).

## Причина

Локальная смешанная сеть нужна для проверки смены ключей, передачи служебного контекста и восстановления подписанта. Нативный импорт раньше принимал только `minter-mainnet-5` с первой высотой 10 197 000. Использовать это имя для синтетического genesis нельзя: существующая проверка требует точный официальный файл.

## Решение

Для нативного пакета пользовательской сети получатель явно передаёт доверенный genesis вместе с доверенным SHA-256 манифеста. Манифест содержит `genesisSha256` точных байтов файла и `transactionChainId`. Имя цепи и начальная высота берутся из genesis; начальная высота проверяется также в `state.pb` и AppDB снимка. При экспорте digest берётся из сохранённого native cursor, созданного при инициализации от genesis.

Проверка файла, полей идентичности и подписанных якорей выполняется до открытия базы. AppDB и `frozenReferences`, для которых нужно дерево снимка, проверяются перед атомарной публикацией головы. Отказ на этом шаге допускает повтор с исправленным доверенным пакетом в том же каталоге.

`NativeSync::open_checkpoint` и `open_network_checkpoint` сохраняют сигнатуры. Добавочный `open_checkpoint_for_genesis` принимает путь genesis и необязательную пару списка пиров с timeout. CLI использует существующее сочетание `--genesis --checkpoint`; отдельного режима обхода проверок нет.

## Mainnet и старые базы

Без явного genesis импорт mainnet сохраняет прежние значения: первая высота 10 197 000 и ID транзакций 1. Старые манифесты без новых полей и курсоры без genesis digest остаются допустимыми. В уже установленной базе проверка такого пакета по-прежнему может использовать только манифест, если якоря и требуемая история уже сохранены.

Если новые поля у mainnet присутствуют, проверяется официальный SHA-256 и ID 1. Любой явно переданный genesis с именем `minter-mainnet-5` должен совпасть с официальным файлом по точным байтам. Явный путь выполняет полную предварительную проверку `state.pb` и `blocks.pb` и при повторном открытии. Legacy-курсор с digest `None` разрешён для mainnet, в том числе при переданном официальном genesis; для пользовательской сети отсутствие сохранённого digest является ошибкой.

Ранняя ветка восстановления проверяет сохранённые имя сети, первую высоту, ID транзакций и genesis digest. Обычный Go/ABCI-импорт остаётся отдельным mainnet-путём с прежним контрактом.

## Передача состояния

Формат `snapshot.zlib`, IAVL, AppDB store names и протокол Tendermint 0.34 сохраняются. Дополнительная идентичность и `frozenReferences` входят в доверенный манифест нативного пакета. Его общий предел — 1 МиБ. State Sync использует те же проверки импорта, что и локальный файл.

Сквозной сценарий — `tools/verify_candidate_key_network.py`: наказание меньшего валидатора, смена его ключа, экспорт непустого контекста, передача снимка и истории по P2P, повторная смена ключа и запись той же строки остатков. Контроль без контекста должен обнаружить несовпадение AppHash до фиксации неверного блока. Затем действующий валидатор меняет ключ: прежний подписывает H+1, новый после штатного перезапуска — H+2; восстановленный наблюдатель продолжает цепь.

`tools/verify_checkpoint_genesis_mainnet.py` отдельно проверяет настоящий mainnet-пакет: свежий импорт, восстановление только по старому манифесту, явный официальный genesis и отказ неверным новым полям до создания базы. Эти проверки не заменяют историческую сверку всех правил Minter и проверку обычной ноды в действующей сети.
