# 0011: Локальное управление общим контроллером

Дата: 15 ноября 2026. Статус: принято для контроллеров текущего пользователя.

Одного наблюдения через HTTP API недостаточно: GUI должен останавливать ноду, запущенную из CLI, а CLI — дочерний процесс GUI. Управление остаётся в `minter-node-control`, чтобы full/light использовали один порядок закрытия базы и освобождения блокировок.

Используются Unix domain socket и Windows named pipe с проверкой пользователя обеих сторон. Unix-каталог приватен (0700), socket — 0600; Windows descriptor содержит protected DACL с единственным разрешением текущему SID, remote clients запрещены. Адрес выводится из идентичности папки данных, поэтому символьная ссылка, Unicode, пробелы и Windows-регистр не создают другой профиль. Настройки и ключи не передаются. Транспорт не добавляет TCP-порт.

JSON-протокол версии 1 имеет фиксированную рамку длины, лимиты и таймауты. Доступны только status/stop. Случайный instance ID связывает stop с наблюдавшимся владельцем. CLI cleanup использует отдельный `stop_owned`, который не переключается на заменившего владельца. После завершения worker сервер закрывает listener и Unix pathname, закрывает журнал, освобождает обе leases и только затем отвечает stop-клиенту. Исчезновение IPC не заменяет подтверждение остановки; ошибки worker сохраняются.

Терминальная ошибка не заменяется случайным HTTP-ответом на том же порту. Новый подтверждённый IPC-владелец доступен для управления, а прошлый собственный сбой показан отдельно как previousError. Без IPC чтение light-кэша удерживает data lease: `light status` тоже открывает redb эксклюзивно.

Это управление пользовательскими контроллерами. Системные службы и процесс другого пользователя требуют отдельного жизненного цикла; нода без контроллера наблюдается через API. При выходе GUI не скрывает новую ошибку остановки; уже показанную терминальную ошибку можно подтвердить явным выходом.

Контракт и команды приёмки: [local-node-control](../specs/local-node-control.md). Схемы RocksDB/redb и консенсус не меняются.
