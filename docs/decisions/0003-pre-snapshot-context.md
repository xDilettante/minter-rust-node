# ADR-003: компактная история до снимка

14 ноября 2026 года. Принято для нативного узла Tendermint 0.34.19.

## Причина

После State Sync приложение располагает состоянием на H и тремя опорными блоками, но не заголовками и составами валидаторов на более ранних высотах. Проверка доказательств требует этих данных и отметок уже включённых доказательств. Полное повторное исполнение истории противоречит назначению быстрого старта.

Go-эталон `a3aac90a4f7995fccaf3cd4e4c34c89ff0c7544c`, `third_party/tendermint/evidence/verify.go`, загружает старый заголовок и набор валидаторов. `types/vote_set.go` ограничивает набор 10 000 голосами. Проверка связи и хеша commit опирается на существующий `minter_p2p::verify::verify_link`.

## Решение

Офлайн-команды `minterd native-history export/import/status` переносят отдельную компактную историю. Файл начинается с `MINTER-CONTEXT\x01`, затем идут protobuf-пакет с цепочкой, высотой и BlockID опоры H, нижней высотой F и ровно H−F записей в порядке H−1…F. Лишние байты и недостающие записи, включая EOF точно между записями, отклоняются.

Запись содержит signed header, состав валидаторов и список включённых доказательств. Она не содержит тела транзакций. Каждый предшественник проверяется по уже доверенному следующему заголовку: соседство высот, цепочка, BlockID, hash заголовка, hash обоих составов, время, все подписи и кворум commit. Дополнительно hash **полного выбранного commit** должен совпадать с `LastCommitHash` следующего заголовка. Одного достаточного кворума мало: часть подписей можно удалить, сохранив кворум и изменив последующую классификацию доказательств.

Для существующего полного блока используется `LastCommit` из следующего блока, если он уже сохранён. Seen commit может содержать поздние подписи, отсутствовавшие в реально выбранном следующем блоке. На вершине используется сохранённый seen commit. Списки включённых доказательств привязаны к `EvidenceHash`; повторяющиеся доказательства отклоняются.

RocksDB хранит старые заголовки и включённые доказательства под отдельным префиксом. Составы валидаторов разделяются по проверенному hash: сохраняются ключи и веса, без приоритетов proposer. Это не восстанавливает исторические приоритеты для подписания. Одна синхронная batch-запись сохраняет контекст, состав, отметки включения и сдвигает нижнюю проверенную границу ровно на одну высоту. Корень приложения, IAVL, метаданные исполнения и диапазон выдаваемых полных блоков не меняются.

При обрыве файла корректный непрерывный префикс остаётся зафиксирован. Команда возвращает ошибку, повтор проверяет существующий префикс и продолжает. Повторный импорт полного файла не добавляет записи. Повторный экспорт из компактной истории сохраняет исходные байты подписей и включённых списков.

## Ограничения ресурсов

Манифест ограничен 16 КиБ, кадр записи — 108 МиБ. Внешние вложенные сообщения представлены bytes до предварительной проверки. Каждый signed header и набор валидаторов ограничен 8 МиБ; число вложенных валидаторов, подписей и обвиняемых — 10 000. EvidenceList разбирается по одной записи, с проверкой вложенных счётчиков перед `prost::decode`. Эти пределы также действуют внутри light-доказательств. Длина файла не определяет размер одномоментного буфера; история обрабатывается последовательно.

## Проверка и границы этапа

На Windows 11 и Ubuntu 24.04 восстановлен настоящий снимок H40 700 741 и импортирован контекст H40 699 717–40 700 740. Независимый Go проверяет 1 024 записи, два участка состава валидаторов, точный EOF и SHA-256. Проверены неправильная цепочка, разрыв, обрыв между записями, продолжение, повтор, хвост файла и побайтный повторный экспорт. Приложение затем исполняет реальный H40 700 742 с подписанным ожидаемым AppHash. Этот диапазон не содержит доказательств. Отдельный unit-тест проверяет настоящее подписанное DuplicateVoteEvidence, его включённый hash, root и дубликат.

Автоматическая загрузка и упаковка достаточного окна добавлены в [ADR-004](0004-snapshot-history-bundle.md). Очистка этого окна и сквозная проверка включения доказательства с высоты ниже снимка остаются отдельными работами. Офлайн-путь и использование добавленной истории проверяющим кодом не закрывают всю приёмку консенсуса.
