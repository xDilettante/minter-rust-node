# 0010: Кооперативная отмена начального восстановления

Дата: 15 ноября 2026. Статус: принято для импорта снимка и обязательной истории.

Десктопный контроллер завершал дочерний процесс через 40 секунд, если тот ещё восстанавливал базу и не слушал stdin. Отмена уже выполняющегося Tokio `spawn_blocking` не прекращает синхронную работу и не подтверждает закрытие RocksDB.

До открытия базы запускается один наблюдатель Ctrl-C/SIGTERM/EOF. После его первого poll управляющий код получает подтверждение регистрации. Один `OperationControl` передаётся в импорт и рабочий цикл. Синхронные чтения проверяют атомарный флаг и возвращают типизированный `OperationCancelled`, сохранённый через I/O и anyhow. Исходные ошибки не заменяются успехом по наличию флага. Наблюдатель и фоновые службы завершаются с проверкой результатов.

Обычные commit и финальная публикация снимка сохраняют прежнюю атомарность. Между промежуточными пакетами импорт можно остановить, оставив intent и узлы без готового head. Intent native-импорта дополнительно закрепляет SHA-256 всего доверенного манифеста. Старый snapshot-only intent принимает первую native-идентичность только при аутентифицированной установке; простое открытие её не закрепляет. Старый бинарный импортер отвергает расширенный незавершённый intent. Формат завершённой базы и прежние публичные методы сохраняются.

Отмена чтения истории сохраняет требуемый кэш и неполную готовность. После проверки последнего точного EOF разрешена запись verified-маркера; кэш удаляется только при готовой истории. Уже начатое сетевое чтение ограничено таймаутом SDK. Крупная очистка, экспорт и построение genesis требуют отдельной работы. Аварийный предел контроллера остаётся.

Контракт и сценарии приёмки: [bootstrap-cancellation](../specs/bootstrap-cancellation.md). Новый API использует явный `CheckpointSource`, чтобы источник, доверие, genesis и State Sync peers передавались совместно с control без глобального состояния.
