# Штатная отмена экспорта

`native-snapshot` и `native-history export` регистрируют Ctrl-C/SIGTERM и необязательный EOF stdin до открытия RocksDB. Один `OperationControl` сопровождает открытие, обход IAVL, запись истории и вычисление SHA-256/chunk hashes. Обычная ошибка worker сохраняется даже при одновременной отмене. Старые API без control сохраняют формат и результат.

Отдельный `ExportStage` и `with_export_progress` различают узлы снимка, поиск границы истории, записи истории и байты хеширования снимка/истории/anchor. Прежний `MaintenanceStage` и его callback не расширяются. Callback экспорта может запросить типизированную отмену. SHA anchor обрабатывается порциями 64 KiB; SHA снимка и истории — State Sync chunks по 10 000 000 байт. Чтение больших файлов checkpoint также использует контролируемый reader. Декодирование одного ограниченного по размеру блока и уже начатый системный вызов завершаются до возврата отмены. Снимок закреплён RocksDB view; экспорт не меняет голову, AppHash, доступные версии или политику хранения.

Все объёмные данные создаются во временных файлах рядом с назначением. Отмена до публикации удаляет временные файлы и не создаёт целевой каталог/файл. Существующее назначение не перезаписывается. После последней проверки отмены начинается короткая публикация готовых файлов: она заканчивается без новых проверок отмены, manifest записывается последним, и поздний запрос остановки не превращает законченный экспорт в отменённый. Ошибка файловой системы во время публикации остаётся ошибкой; атомарная публикация целого каталога при аварии питания в эту часть не входит.

Приёмка: отмена до работы, во время обхода IAVL, истории и хеширования; повторный экспорт даёт те же bytes/SHA-256 и импортируемый пакет. Windows и нативная Ubuntu проходят реальные CLI-сценарии на закрытой копии mainnet-базы с неизменными входными SHA-256, штатным выходом и повторным открытием. Проверки исходного дерева, полного workspace и Clippy проходят на обеих ОС. Genesis и явная компакция SDK остаются отдельными частями.
