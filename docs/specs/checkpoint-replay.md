# Спецификация: продолжение Go-эталона из checkpoint

`tools/replay_mainnet_genesis.go` сохраняет прежний запуск от genesis и получает необязательный префикс `--checkpoint PACKAGE MANIFEST_SHA256`. Остальные аргументы: `GENESIS BLOCK_SHARDS NEW_OUTPUT THROUGH [CHECKPOINT_HEIGHT ...]`.

1. Genesis остаётся точным официальным файлом minter-mainnet-5. Манифест исходного нативного пакета принимается по явно переданному доверенному SHA-256. До создания выходного каталога проверяются хеши/размер снимка, state.pb, blocks.pb и согласованность сети, высоты, AppHash и BlockID.
2. Наборы валидаторов из state.pb связываются с тремя якорными блоками и их коммитами. Сырые части содержат блок исходного checkpoint и последовательное продолжение. Известный checkpoint берётся из ранее проверенного непрерывного Go replay; проверка его происхождения остаётся у вызывающего сценария.
3. Go восстанавливает физический снимок, проверяет корень и исполняет блоки H+1…THROUGH. Обычный цикл проверки подписей, AppHash, корня результатов и изменений валидаторов используется в обоих режимах. Коммит THROUGH+1 проверяется с помощью блока THROUGH+2.
4. `result.json.from` обозначает первый исполненный блок; `startingCheckpoint` и его доверенный SHA отдельно описывают исходное состояние. ABCI-трасса содержит только исполненные блоки. Снимки и итоговый результат публикуются после завершения проверки.
5. Регрессия сравнивает все ABCI-байты и корни 21 ранее проверенного блока 10 523 500–520 со старой трассой от genesis. Прежний режим дополнительно проверяется на первом блоке эпохи: его заголовок сверяется с `genesis.AppHash`, который может быть пустым, отдельно от внутреннего IAVL-корня после InitChain. Неверные SHA, пакет/сеть/высота и отсутствующий якорь отклоняются.
6. Приёмка режима включает 20 000 новых блоков по 10 543 520, сравнение Rust с Go и восстановление до/после Commit на Windows и Ubuntu. Этот этап выполнен и зафиксирован в отчёте; историческая совместимость всей цепочки остаётся отдельным открытым критерием.
