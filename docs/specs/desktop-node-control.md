# Общие настройки и управление десктопной нодой

## Контракт

GUI Tauri и `minterctl node` используют одну библиотеку `minter-node-control`: формат настроек, проверку входных данных, сборку аргументов, запуск, штатную остановку, статус и ограниченный журнал. Библиотека запускает `minterd` и `minterctl light` из каталога текущего исполняемого файла. Команды передаются отдельными аргументами, без оболочки. API и P2P десктопного профиля слушают только loopback.

Новые настройки полной ноды выбирают профиль `full`: 120 версий состояния, 100 000 высот событий и тел блоков. `archive` сохраняет дальнейшие данные без очистки. `custom` задаёт три лимита отдельно; ноль сохраняет дальнейшие данные, одно полное тело недопустимо. GUI передаёт именованные профили через существующий `minterd native-sync --storage-profile`, а custom — тремя числовыми флагами. Переключение профиля не восстанавливает ранее удалённую историю. Первоначальный снимок также ограничивает доступную историю.

Загрузка старого GUI JSON с `archive: true` сохраняет архивный режим. Старый `archive: false` сохраняет прежний `keepVersions`, а события и тела блоков остаются без лимита: это custom. Миграция не должна молча вводить новый лимит блоков. Неизвестные, повторяющиеся или неоднозначные поля отклоняются. Запись настроек остаётся атомарной. Между GUI и CLI действует файловая блокировка канонического пути конфигурации, включая symlink файла: управляющий процесс удерживает её до завершения дочерней ноды; другая попытка сохранения или запуска получает ошибку. Дополнительно удерживается блокировка канонической папки данных, чтобы два различных файла настроек не запускали два супервизора над одной папкой. Чтение и наблюдение через API разрешены.

`minterctl node run --config FILE` запускает тот же контроллер в foreground и останавливает его по Ctrl-C. Дополнительный `--shutdown-on-stdin-close` позволяет родителю штатно завершить CLI-супервизор. `node settings`, `node status` и `node logs` читают тот же файл. Для первого создания используется `node init --config FILE --data-dir DIR`; существующий файл не перезаписывается. `node stop` и GUI могут управлять другим экземпляром общего контроллера того же пользователя и папки данных через [локальный канал](local-node-control.md), включая full/light и восстановление снимка. `managed` обозначает собственный процесс, `controllable` — возможность управления, `controlId` связывает команду с конкретным запуском. Нода без такого контроллера остаётся доступна для наблюдения через API. Автозапуск и службы остаются отдельной задачей.

## Проверка

- Rust: миграция прежних настроек без потери лимитов, отклонение неоднозначного JSON, три профиля и корректные аргументы с Unicode/пробелами, существующие проверки срока доверия и журнала.
- Frontend: форматирование, Svelte/TypeScript, production build; выбор профилей и понятное предупреждение о доступной истории.
- Windows и Linux: сборка общего CLI/GUI, реальный Go-пир и WebView, запуск/остановка полной и лёгкой ноды, повторное открытие базы и сравнение AppHash. Отдельно проверить foreground CLI по тому же JSON и штатную остановку через закрытие stdin.
- Реальные установщики и настоящая графическая Ubuntu проверяются отдельно от браузера или контейнера с Xvfb; результаты нельзя смешивать.

## Остановка при начальном импорте

Полная нода регистрирует Ctrl-C/SIGTERM и EOF до начального восстановления. Импорт снимка и чтение обязательной истории получают общий `OperationControl`; отмена дожидается закрытия базы и оставляет неопубликованный импорт для повторного запуска с тем же доверенным пакетом. Показанный прогресс IAVL ещё не означает готовность снимка. Подробный контракт, совместимость незавершённого импорта и границы отмены описаны в [спецификации](bootstrap-cancellation.md).

Лёгкий супервизор дожидается окончания текущей одноразовой команды, включая закрытие redb. В Linux дочерние процессы получают отдельные группы, чтобы терминальный SIGINT принимал супервизор. Ошибка последней light-команды сохраняется при остановке, включая остановку во время паузы перед повтором. Через 40 секунд контроллер завершает процесс принудительно, дожидается его выхода и сообщает ошибку в GUI и коде возврата CLI. Этот предел сохраняется для зависшего SDK, уже начатого сетевого чтения или других операций без кооперативной отмены. Крупная очистка и построение состояния от genesis пока проверяют запрос лишь до и после операции.
