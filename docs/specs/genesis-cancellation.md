# Штатная остановка построения genesis

Один `OperationControl` сопровождает открытие базы и создание genesis в native-ноду; обработчики Ctrl-C/SIGTERM и необязательного EOF регистрируются до открытия. ABCI InitChain использует тот же контроль подготовки, отдельно от обычного исполнения блоков. Прежние публичные методы без control сохраняют результат и форматы.

Чтение исходного файла, SHA и канонический hash app_state, разбор JSON, крупные циклы подготовки операций, применение мутаций IAVL и обход физических узлов проверяют отмену. Прогресс вынесен в отдельный `GenesisStage`, без изменения callback обслуживания/экспорта. Прогресс означает обработанные байты/записи/операции/узлы, а не опубликованную голову. Уже начатый системный вызов или ограниченная библиотечная операция завершается до проверки отмены.

До последней проверки перед атомарным WriteBatch cancellation возвращает типизированную ошибку и не публикует голову, метаданные или часть дерева. Повтор начинает подготовку заново с того же genesis; промежуточный готовый head не объявляется. Все fallible native-параметры, валидаторы и cursor готовятся перед публикацией; callback метаданных получает окончательный IAVL-корень. SHA исходного файла и полное native-состояние сохраняются с ним одним пакетом, поэтому новая база открывается до первого блока без повторного файла. Если файл указан повторно, точный SHA проверяется: изменение времени или consensus_params при том же app_state отклоняется. Старый genesis без сохранённого native cursor может однократно принять явно предоставленный оператором исходный файл через отдельную атомарную запись метаданных, без перестроения дерева; доказать отсутствовавший исторический digest по старой базе невозможно. После начала атомарной записи она заканчивается; поздняя остановка сохраняет полностью опубликованное состояние. Последующая подготовка сервиса может обработать поздний сигнал, сохраняя этот готовый head. Обычный Commit блока не получает флаг подготовки и не становится отменяемым.

Приёмка: отмена до работы, во время разбора/подготовки, применения мутаций и физического обхода; повтор и совпадение корня/операций с прежним Go-эталоном. Официальный genesis minter-mainnet-5 (SHA 906c2ab969389853247305b0930c92f5906dc1962cd3075832ca4d7ab0fe55a5, app_state 127 580 513 байт) проходит CLI и ABCI на Windows и нативной Ubuntu. Проверяются выход без принудительного завершения, повторное открытие, сохранность входов, повторная инициализация, AppHash и существенные чтения Go. Полный workspace, Clippy и release проходят на Windows/Linux. GUI подключается к тому же пути native-подготовки; кнопочная проверка фиксируется отдельно, без подмены нативной Ubuntu средой WSL.

Текущее покрытие: готовы остановка IAVL, чтение/разбор JSON порциями 64 KiB, исходный и канонический SHA, повторная проверка InitChain и атомарная native-публикация с идентичностью файла. Внутренние циклы общей подготовки, подключение сигнала ABCI и полная сквозная приёмка большого файла/GUI остаются в работе; весь контракт ещё не объявляется выполненным.
