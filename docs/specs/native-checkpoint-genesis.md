# Spec: доверенный genesis нативного checkpoint

## Цель и область

Модуль `native-checkpoint` должен переносить контекст смены ключа через настоящий пакет и State Sync в локальной смешанной сети. Существующий импорт привязан к `minter-mainnet-5` и H10 197 000. Для испытания нужен штатный путь пользовательской сети с явным доверенным genesis, без обхода проверки основного genesis.

Работа — техническая часть уже порученных полного переноса и сквозных проверок. Существующие разрешения на разработку и продолжение работы применяются к этой реализации. Выпуск и работа с реальными ключами валидаторов сюда не входят. Это одна способность существующего модуля: привязка checkpoint к идентичности сети.

Предпосылки: стандартные mainnet-команды сохраняются; genesis доверяется по точным байтам, как при текущем `NativeSync::open`; манифест по-прежнему требует доверенный SHA-256. Go snapshot/IAVL и сетевой протокол 0.34 не меняются. Дополнительных зависимостей, схемы IAVL и CI не требуется.

## Контракт

1. Mainnet без `--genesis` сохраняет нынешний путь, ID транзакций 1 и H10 197 000. Файл с именем сети `minter-mainnet-5` всегда проверяется по существующему официальному SHA-256; синтетический genesis под этим именем отклоняется.
2. Нативный пакет пользовательской сети содержит необязательные для старого mainnet `genesisSha256` и `transactionChainId`. Для пользовательской сети они обязательны. Получатель передаёт тот же доверенный файл через сочетание `--genesis` и `--checkpoint`. Имя сети, точные байты, начальная высота и ID транзакционной сети должны совпасть. В новом явном genesis-пути пакет, включая state.pb и якоря, проверяется до открытия базы. Без файла, с другой сетью/байтами/ID/высотой импорт отклоняется до открытия базы.
3. Начальная высота в `state.pb` и AppDB проверяется относительно доверенного genesis. Несовпадение AppDB обнаруживается до публикации головы. SHA-256 genesis сохраняется в существующем native cursor; повторное открытие с другим файлом отклоняется.
4. Старые публичные `open_checkpoint`/`open_network_checkpoint` сохраняют сигнатуры. Добавляется `open_checkpoint_for_genesis(path, network, package, digest, genesis, keep, peers)`, где peers — необязательная пара списка адресов и timeout.
5. Экспорт пользовательской сети берёт имя, высоту и ID из текущей цепи, digest из сохранённого cursor. Он не придумывает новую доверенную опору. `frozenReferences`, история, подписи и существующие пределы проверяются общим кодом.
6. Старый mainnet-пакет без новых полей и cursor с `genesis_sha256=None` сохраняют прежнее чтение и восстановление, включая ленивое чтение якорей уже установленной базы. При переданном официальном genesis legacy None не считается чужим digest; пользовательский None всегда отказ. Если новые поля присутствуют у mainnet, они проверяются по официальному digest и ID1, а не игнорируются. Ранняя recovery-ветка сверяет сохранённые chain ID, initial height, transaction ID и digest с проверенной Identity.

## Стек и структура

Rust, существующие `serde_json`, `sha2`, Tendermint 0.34, RocksDB. `crates/minter-app/src/native_sync.rs` — чтение/проверка genesis и конструкторы; `checkpoint.rs` — AppDB; `native_sync/checkpoint.rs` — пакет и якоря; `native_sync/export.rs` — экспорт; `bin/minterd/native_sync.rs` — CLI. Тесты доверия — Rust unit; сеть и передача — `tools/verify_candidate_key_network.py`; локальные Go-генераторы используют только открытые тестовые ключи.

## Команды

```text
cargo test --locked -p minter-app --lib checkpoint_genesis
cargo test --locked --workspace
cargo clippy --locked --workspace --all-targets -- -D warnings
cargo build --locked --release --workspace
minterd native-sync --db ./receiver --checkpoint ./package --checkpoint-sha256 <digest> --genesis ./genesis.json --snapshot-peer <id@host:port> --peer <id@host:port> --through <height>
python tools/verify_candidate_key_network.py <minterd> <minterctl> <tendermint> <go-app> <fixture-tool> <transaction-tool> <base-fixture> <new-output>
```

Сохраняются существующие окружения Windows/MSVC и Linux/clang; общие каталоги Cargo не запускаются параллельно в одной ОС.

## Стиль

Доверие проверяется до мутации; ошибки содержат конкретное несовпадение. Например:

```rust
ensure!(identity.chain_id.as_str() == manifest.network, "checkpoint network differs from genesis");
```

Именованные внутренние типы связывают идентичность; не добавляются флаги отключения проверки. Существующий parser AppDB переиспользуется; mainnet-ограничения обычного Go/ABCI-импорта сохраняются.

## Проверки и критерии

- Положительный/отрицательный Rust-тесты: пользовательская сеть с точным genesis; отсутствие файла, чужая сеть, изменённые байты, ID и начальная высота; сохранённый отказ поддельному mainnet genesis.
- Локальная сеть Rust-валидатора и Go Tendermint исполняет смену ключа; сохранённый контекст непуст. Экспорт, импорт/State Sync и ещё одна ротация с записью той же frozen-строки совпадают с Go.
- Отрицательный контроль без контекста действительно обнаруживает различие. Неверные границы контекста отвергаются, исправленный импорт возобновляется. Пакет >16 КиБ проходит serving/приём.
- Новый ключ действующего валидатора подписывает с H+2 после штатного завершения прежнего процесса; Go подтверждает составы, подписи, AppHash, результаты и EndBlock.
- Повторяются проверки mainnet checkpoint на реальных подписанных данных; обе ОС проходят применимые тесты, Clippy и release. Эти критерии не заменяют остальные пункты общей миграции.

## План и задачи

Порядок: общий genesis identity → проверка identity до открытия и при восстановлении AppDB → экспорт/CLI → сквозной стенд и mainnet-регрессия. Реестр — существующие `outputs/tasks/plan.md` и `outputs/tasks/todo.md`, без дублирования проекта новым tracker.

1. Чтение и проверка genesis, с сохранением официального mainnet-ограничения (native_sync + тесты).
2. Добавочный конструктор и проверка пакета/AppDB/state.pb; проверенные отрицательные случаи (checkpoint + native_sync + root checkpoint).
3. Поля экспорта и CLI-сочетание `--genesis --checkpoint`; документация (export + CLI + README).
4. Сеть, снимок/State Sync, H+2 и обе ОС; архив происхождения и обновление общего плана.

Границы: сохранять существующие API и формат IAVL; не читать и не публиковать пользовательские секреты; не менять vendor и официальную идентичность mainnet; не отключать неуспешные проверки ради зелёного прогона. При ошибке возвращаться к первой различающейся высоте и причине.
